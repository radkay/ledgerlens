# Proposed LedgerLens implementation lanes

Use one Build agent session per worktree from the current `origin/dev` when Ron starts a lane. D-009 holds Runtime agent and release-evidence implementation until the live digital W-2 increment publishes and reverse lineage is available.

| Lane | Worktree and branch | First task | Owned files | Done when |
|---|---|---|---|---|
| Synthetic fixtures and extraction | `../ledgerlens-extraction` · `codex/extraction-w2` | Start with digital W-2. Extend the Bronze adapter and synthetic fixtures to digital 1099 and 1098 forms and scanned documents using `ai_parse_document`. | `provisioning/fixtures.py`, `src/ledgerlens/extraction/**`, `tests/test_fixtures.py`, `tests/test_extraction*.py` | Digital and scanned W-2, 1099, and 1098 fixtures have stable SHAs and canonical field IDs. The adapters produce the expected Bronze records or a contract-shaped failure. |
| Processing and evaluation | `../ledgerlens-processing` · `codex/processing-w2` | Publish one digital W-2 using frozen inputs, run-stamped writes, lineage, and the final publication marker. | `src/ledgerlens/processing/**`, `src/ledgerlens/evaluation/**`, `tests/test_processing*.py`, `tests/test_evaluation*.py` | Dev has one live published increment with reverse lineage. Replay, duplicates, partial writes, review and recall are verified, and evaluator aggregates stay isolated from the private key. |
| Catalog governance | `../ledgerlens-governance` · `codex/catalog-governance` | Propose a protected contract amendment for the mask, reviewer grants, and current-view review findings. | `provisioning/provision.py`, `provisioning/schema.sql`, `provisioning/state.sql`, `tests/test_governance*.py` | Approved grants and masks pass allow/deny checks for each identity, and two published runs verify the current/history semantics without double-counting. |
| Dashboard and workbench | `../ledgerlens-app` · `codex/app-workbench` | Build a fixture-backed dashboard pinned to one publication and a masked workbench interface. | `src/ledgerlens/app/**`, `tests/test_app*.py` | A reader can inspect published Gold and lineage, the reviewer has only the approved decision actions, and identity and publication isolation are tested. |
| Integration and runtime wiring | `../ledgerlens-integration` · `codex/integration-wiring` | Wire the processing and evaluation entry points into the dev bundle once their first tasks can be deployed. | `databricks.yml`, `resources/**`, `.github/workflows/**`, `scripts/databricks_smoke.py`, `src/ledgerlens/bootstrap_job.py`, `tests/test_bootstrap.py` | The CI principal deploys under its own identity, the jobs run as the scoped processor and evaluator, and the dev smoke run verifies publication and sensitive-data denials. |
| Runtime agent and evidence | `../ledgerlens-runtime-evidence` · `codex/runtime-evidence` | After the live W-2 and reverse lineage are available, start with a managed dbsql MCP call against Gold. Then implement the custom LedgerLens MCP server and the Runtime agent. | `src/ledgerlens/mcp/**`, `tests/test_mcp*.py`, `docs/evidence/**`, `README.md` | The custom MCP server and Runtime agent complete a bounded Gold query and reverse-lineage trace. Managed dbsql MCP verification has its own reproducible evidence. Ron's supplied Nov 23 probes are linked after review, and README claims match the observed results. |

Run live job verification through post-merge integration with one in-flight workflow per environment. The bundled Processing and Evaluation jobs each set `max_concurrent_runs: 1`.

The integration lead coordinates protected `CONTRACT.md` amendments, shared dependency and lockfile changes, and cross-lane job and app entry points. Ron initiates the lanes and supplies the November 23 probe artifacts.
